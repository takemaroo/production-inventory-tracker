One line per decision, newest at the bottom. Record anything a later agent might otherwise undo or ask about again: choices made without the owner, scope rulings, and disputes settled by the tech lead.

| 1 | 2026-11-11 | `docs/01-prd.md` replaces `README.md` as the source of truth wherever the two differ. The README is updated at release. | The design changed a lot in the owner interview. | Owner | yes |
| 2 | 2026-11-11 | Two fixed stock locations, Warehouse and Production storage, replace "one warehouse". General multi-warehouse support is Later. | Leftover stays in production storage and must be tracked there. | Owner | yes |

| 18 | 2026-11-11 | If a Pending return's quantity exceeds the production-storage stock when it is received (e.g. after a write-off), the receipt is rejected with `409` "Not enough stock…". | 19 | 2026-11-11 | Stack: .NET 10 LTS (installed; .NET 11 is short-term support and not installed), ASP.NET Core controllers, EF Core 10.0.15 with SQLite, Identity + JWT bearer 10.0.15, built-in OpenAPI, xUnit v3 4.0.3 on Microsoft.Testing.Platform (selected in `global.json`). | 20 | 2026-11-11 | Stock is calculated with SQL SUM over movements, filtered by item. There is no stored balance table. | Matches D-2 exactly and cannot drift. Measured about 140 ms for a grouped SUM over 100,000 movements on the owner's machine. | tech-lead | no |
| 21 | 2026-11-11 | Every data-changing request does its reads, checks and writes in one `InWriteTransactionAsync` call. On SQLite this is `BEGIN IMMEDIATE` (checked by experiment), so writes are serialized. A unique filtered index on `Status = 'InProduction'` is the backstop for one order in production. On PostgreSQL, add `pg_advisory_xact_lock` in the same helper. | Meets PRD section 5 consistency with one simple rule. | tech-lead | no |
| 22 | 2026-11-11 | Production order, complementary order and return numbers are the tables' primary keys. Status history is built from the timestamp and user columns; there is no history table. | Simplest model that gives each its own sequence and the audit trail (AC-05.3). | tech-lead | no |
| 23 | 2026-11-11 | A body that is not valid JSON, or has a wrong JSON type, is rejected with `400` before the `404` check. This is the only deviation from design 2.2's check order. | tech-lead | no |
| 24 | 2026-11-11 | Send and complementary send ranges are rounded to 3 places first; a quantity is accepted when it is within the rounded limits shown to the user. Percentage thresholds use unrounded values (AC-20.4). | The accepted range is exactly what the API displays. | tech-lead | no |
| 25 | 2026-11-11 | Sign-in order: unknown or inactive user → invalid-credentials (no failure counted); locked → account-locked; wrong password → counted, invalid-credentials (the fifth failure starts the 15-minute lock); right password → count reset. | Makes AC-01.3 and AC-01.4 exact. | tech-lead | no |
| 26 | 2026-11-11 | Tokens: 8 hours, no clock skew. Each request checks that the user is active and that the token's security stamp matches.
